# Worker hardening

The worker still uses the existing Firestore queues. One worker process runs one intake attempt followed by one generation attempt; heavy jobs are not parallelized. Empty/error passes wait one second. One cleanup pass may run alongside processing, at most once per minute.

## Implemented behavior and defaults

- SIGINT/SIGTERM stop new claims and abort active work. A shutdown during claim prevents external dispatch. Eligible claimed work with durable evidence of no provider dispatch can be released without spending its retry budget; expired resources or legacy/unknown dispatch evidence do not qualify. Workers await an outstanding lease renewal before returning. Leases default to 60 seconds, with non-overlapping renewals every 20 seconds; stale ownership cannot publish a result. Generation records provider dispatch durably and distinguishes proven pre-dispatch releases from paid attempts. Lease recovery preserves that evidence even when a late failure has already marked the expired claim discarded; explicit transcription retries retain the same protection. Missing/legacy dispatch evidence still spends the bounded retry budget. Intake hard crashes retain the bounded retry budget (three attempts per intake admission), rather than unlimited recovery.
- Intake reserves scratch space for two accepted maximum-size source files plus 256 MiB. Audio reserves one source plus bounded WAV output; video reserves one source plus 100 MB output, each with 256 MiB headroom. Reservations are process-local and released after cleanup. Scratch reservation and directory-creation errors are retryable; cleanup failure emits a generic path-free diagnostic and cannot overwrite a successful result. The minute cleanup pass removes matching temporary directories older than 24 hours.
- Media admission checks all reported video streams before packet scanning: dimensions at most 8192, pixels at most 4096 × 2160, frame rate at most 120 for motion video, and at most 32 streams. Attached cover art remains subject to dimension/pixel/stream-count bounds but is exempt from frame-rate checks; cover art alone does not qualify as a video. Rendering selects the actual motion stream (`V:0`) and passes the pixel ceiling to each source decoder (`-max_pixels`). `RIFLO_MEDIA_MAX_DIMENSION`, `RIFLO_MEDIA_MAX_PIXELS`, `RIFLO_MEDIA_MAX_FPS`, and `RIFLO_MEDIA_MAX_STREAMS` override these operational limits with positive integers. These bounds are separate from accepted plan duration/bytes.
- Source bytes are metered while streaming, normalized output bytes are checked again, and packet timestamps supplement container duration. Local media tools use file/pipe protocol restrictions, finite output buffers and deadlines. Source tools run with a restricted environment and owned process group; cancellation escalates from SIGTERM to SIGKILL after 500 ms, with bounded cleanup. Probe/FFmpeg executions use SIGKILL on timeout or cancellation.
- Intake has a 15-minute stage deadline and a three-minute upload deadline. Probe and packet scans have 60-second deadlines, remux/audio 120 seconds, and video encoding 180 seconds. Generation defaults to 180 seconds per stage (`GENERATION_STAGE_TIMEOUT_MS`, range 1000–600000), also capped by accepted batch/resource deadlines. A trace overdue warning is diagnostic, not an extra timeout.
- Storage reads own cancellable SDK/auth worker threads and cap concurrency at eight per process, bytes at 6 GB by default, and duration at 180 seconds. Upload and deletion lanes are separate. Cancellation waits for owned worker termination, including pre-header authentication and HTTP work. Known transport/service/capacity failures remain retryable through audio/video consumers; permanent access/content failures remain terminal. Immutable output paths and ownership checks preserve successful commits when replies are lost.
- YouTube metadata validation admits four concurrent calls per source-access instance and one per account by default (`SOURCE_VALIDATION_MAX_ACTIVE`, `SOURCE_VALIDATION_MAX_PER_ACCOUNT`); account saturation returns 429, total saturation 503, both with `Retry-After: 5`. Admission is shared by preview, create, retry and restore paths, and releases in `finally`. HTTP disconnect or server shutdown propagates cancellation to validation; Drive validation is not subject to the YouTube process cap.
- Progress observation defaults to 100 active streams and five per account per handler, a five-minute lifetime, and 15-second heartbeats. New streaming POST requests reserve observer capacity before new work is authorized; accepted idempotent replays at capacity return a finite SSE acknowledgment with the operation identity and `observation_busy`, so accepted work remains recoverable. Backpressure closes a blocked observer rather than accumulating notifications.
- Structured worker events contain allowlisted identifiers, stage/attempt, safe error codes and durations. Overdue leaf waits are reported without credentials, URLs or arbitrary error text. Optional `RIFLO_WORKER_TRACE=1` provides detailed timing.

## Validation evidence

Final gates on 2026-10-31: `npm run typecheck` and `npm run build` passed; the complete `npm test` run passed **677/677**, with **zero failures, skips, cancellations or todos**, in **205.955 seconds**. SHA-256 snapshots of all 178 source/test/configuration files match before and after the final run (`hash-comparison.json`: no changes). Logs and snapshots are under `artifacts/worker-hardening/`.

Earlier runs remain distinct evidence: the initial incomplete run hit missing Auth/Storage emulators; two subsequent runs were deliberately interrupted for the late-shutdown regression and an outdated credit-exhaustion fixture. The fixture now durably records actual provider dispatch before each expired lease, preserving its paid-attempt exhaustion and credit-release assertions. A completed run against reused emulator data passed 676/677 (`full-test-dirty-emulator.log`): 51 processed retention fixtures left by an interrupted run filled the legacy first page. The exact failing cleanup test then passed on clean data (1/1), its full file passed (6/6), and an independent 51-row fixture demonstrated the same worker advances on pass two. No cleanup implementation or test assertion changed for this harness issue. Both owned demo Firestore databases were reset before the final 677/677 run. After acceptance, the owned emulator processes were stopped and ports 59296–59298 verified closed.

Review evidence: the initial six-turn tool-based Claude review was incomplete. A subsequent input-only Claude Opus 5.5 review completed successfully in 88.5 seconds (one turn, exit 0); its cover-art finding was verified with a native fixture and corrected. Its variable-frame-rate concern was not established and was not implemented as a speculative fix. Independent review and a lean review were also performed; review conclusions supplement, rather than replace, the runnable gates above.

The isolated harness uses `demo-riflo`, Firestore `127.0.0.1:59297`, Auth `127.0.0.1:59296`, Storage `127.0.0.1:59298`, `NODE_ENV=test`, and `/opt/homebrew/bin/{ffmpeg,ffprobe,yt-dlp}`. Native downloader tests use synthetic extractor metadata and localhost media. No `.env` or live provider requests are needed.

## Remaining host acceptance

This is single-worker capacity hardening, not a measured production capacity guarantee. DCI 4K120 is a metadata admission limit, not measured peak RAM. No parallel heavy execution is enabled. Disk reservations do not coordinate other processes or reserve filesystem blocks. A 6 GB source and worst-case one-hour media have not established production throughput, peak RAM or deadline sufficiency; the native one-hour timeline fixture is deliberately tiny. Measure these on the deployment host before changing concurrency or promising capacity. Shutdown/recovery tests do not establish a universal wall-clock bound for every external database operation. No queue migration is part of this work. Polling tuning and independent intake/generation execution lanes are deferred until host measurements justify them.
